# Experiment 1 — PM-Bench baselines: per-category failure analysis

`single_baseline`, corrected (`empty`) fallback, one trace per model.
Generated by `harness/analyze_categories.py`; **every model validated against
PM-Bench's own scorer** (per-task hit/late totals match exactly).

Worked examples of every category are in `exp1_task_taxonomy.md`.

## Findings

**1. `override` is 0/3 for every model, 0.6B through 70B.** Nothing in the set
handles "that task changed, do the new thing instead". This is a harder wall
than cross-day and it does not move with scale at all.

**2. Channel-triggered tasks fail almost completely, and scale makes it
worse.** The three strongest models (Ministral-8B, Qwen3-32B, Llama-70B) each
score **0/15**. Only the two weakest score above zero, and Qwen3-0.6B's 6.7%
arrives with 6 lure selections, so it is noise rather than capability.

**3. Performance is carried by recurring tasks.** Llama-70B reaches 82.1% on
the 28 regular occurrences and 28.3% on the 53 non-regular ones. Models are
doing routine recall, not prospective monitoring. Reporting only the headline
Set-F1 hides this split entirely.

**4. The dominant error is timing, not confusion.** "Real task, wrong step"
outnumbers every other false-alarm kind for every model. Lures are almost
purely a small-model failure: 6-8 for 0.6B/1.7B, zero for most models >=3B.

## Per-task data

`paper_tables/per_task/<model_slug>/`:

- `per_task_outcomes.csv` — one row per scored occurrence: day, task id, label,
  modality, regular, cross_day, cue_channel, target_time, update_action,
  outcome (hit/late/miss/canceled), completed_at
- `false_alarms.csv` — one row per uncredited selection: step, task id,
  attributed kind, modality, cue_channel

## Reproduce

```bash
python harness/analyze_categories.py \
  --log harness/results/<model_slug>/single_baseline/trajectory.jsonl \
  --label <model> --validate --out-dir paper_tables/per_task/<model_slug>
```

`--validate` is not optional when reporting: it re-checks the per-task totals
against the untouched `score_log`. It caught a real undercount during
development (57 occurrences instead of 81) from the recurring-id collapse.

## Caveats

1. **One trace per model.** Measured single-trace spread on unchanged code is
   3.95 Set-F1 points; per-category rates over 7-15 occurrences are noisier
   still. A single cross-day occurrence moves that column by 14 points.
2. `single_baseline` only. The heartbeat setups are held but not analysed here,
   and that is where fallback contamination concentrates.
3. Llama-70B ran 4-bit bitsandbytes; every other model is bf16.
4. Requires `--generation-config vllm` on the actor. See `experiments/README.md`.
